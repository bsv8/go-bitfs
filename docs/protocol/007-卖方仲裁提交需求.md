# 007 · 卖方仲裁提交需求

## 要解决什么

卖方持有买方已签出的累计付款状态，但无法按正常路径完成交易提交时，需要仲裁者补足 2-of-3 所需签名。仲裁者不是买方或卖方的数据库副本，不能只收到一个哈希或 `SpendTxID` 后再向任何一方查询材料。

卖方提交给仲裁者的材料必须是完整原始凭证和原始签名。

## 仲裁者实际做什么

仲裁者不重新判断卖方是否交付了某个文件块，也不重新计算报价或应付款金额。买方对最后累计付款状态的签名已经表达：截至该支付序号，卖方累计应得多少、买方剩余多少。

仲裁者只验证这份状态可执行，然后对同一笔确定交易提供仲裁签名。

```text
不是：仲裁者裁定卖方应得到 X
而是：买方已经签出 X，仲裁者验证后补足交易签名
```

## 为什么不带全部业务历史

仲裁提交不能只带哈希引用，但也不应把全部报价、请求和交付历史无差别重复传输。最低证据是：

```text
完整开池证明
+ 最后完整买方付款状态
```

所有累计付款状态都花费同一基础输出；最后状态是累计值，买方签署它即承接此前金额。001、003、004 仍由双方保存，供审计或未来的交付争议机制使用；当前 V1 卖方仲裁提交不拿它们重新计算金额。

## 单向边界

只有卖方可以发起本步骤。买方不能以卖方未提交交易、未反签金额或未响应为由请求仲裁关闭；买方的路径是等待到期并取得退款或找零。仲裁费用由卖方承担，V1 不从池内静默扣除。

具体证据包、校验和响应见[卖方仲裁提交规范](007-卖方仲裁提交规范.md)。
