# 003 · 最终付款授权规范

003 是买方对本次内容购买和最终累计付款结果的唯一签名授权。它不是只引用报价的弱请求，也不是 005 交易签名；买方签发后，卖方可以在买方拒签本次 005 时按 007 构造仲裁候选交易。

## 签名对象

```text
ContentRequestTermsCBOR = deterministic CBOR(ContentRequestTerms)
BuyerSignature = Sign_buyer(ContentRequestTermsCBOR)
ContentRequestTermsHash = SHA256(ContentRequestTermsCBOR)
```

当前协议 major 为 `2`。`ContentRequestTerms` 的 canonical 字段固定包含：

| 字段 | 约束 |
|---|---|
| `version` | 当前 major `2`。 |
| `quote_terms_hash` | 001 报价哈希，供正常签发和审计使用；仲裁者不回查报价。 |
| `spend_txid` | 唯一费用池锚点。 |
| `base_payment_sequence` | 买方签发时最后接受的状态序号。 |
| `payment_sequence_after` | V2 必须等于 `base + 1`。 |
| `seller_amount_after_sat` | 本次之后卖方的绝对累计金额，不是增量价格。 |
| `miner_fee_rate_sat_per_kb` | 开池时固定的整数费率。 |
| `buyer_pubkey` | 必须等于池的 A。 |
| `seller_pubkey` | 必须等于池的 server。 |
| `selected_arbiter_pubkey` | 必须等于池的 B。 |
| `content_type` / `content_hash` | 请求的 seed 或 block 及其精确哈希。 |
| `delivery_deadline_unix` | 卖方首次接受授权的交付截止时间。 |

外层 `SignedContentRequest` 仍只包含 `version`、原始 `terms_cbor` 和 `buyer_signature`。签名覆盖全部上述字段；任何金额、序号、池角色或费率改动都必须使签名验证失败。

## 买方签发前

买方验证报价、内容关系、池参与者、当前接受状态、余额和价格，并把计算后的绝对 `seller_amount_after_sat` 和目标序号写入授权。禁止卖方或仲裁者根据报价、历史订单或 `PriceSat` 重新计算仲裁金额。

## 卖方接受

卖方必须独立验证授权签名、池锚点、server/A/B、费率、base/target 序号、绝对累计金额、余额和交付期限，并在交付前原子持久化单池请求门闩。过期、过时、余额不足、费率不符或并发授权冲突都必须拒绝；禁止自动 rebase 旧授权。

正常 004 只引用本授权哈希。仲裁请求只提交完整原始 `SignedContentRequest`，不要求 001、004、内容 payload 或历史付款链作为业务证据。
