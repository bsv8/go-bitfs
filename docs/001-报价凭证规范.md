# 001 · BitFS 报价凭证规范

`SignedFileQuote` 是卖方向一个指定买方作出的、自证明的文件出售承诺。它不是数据库记录，也不依赖一个由服务端分配的报价 ID。报价的真值是：

```text
TermsCBOR + SellerPubkey + TermsSignature
```

`TermsCBOR` 是 `FileQuoteTerms` 的 deterministic CBOR 原始字节；`TermsSignature` 是卖方直接对该原始字节的签名：

```text
TermsSignature = Sign_seller(TermsCBOR)
Verify(SellerPubkey, TermsCBOR, TermsSignature)
```

本规范不增加签名域。实现必须保证 `TermsSignature` 只被当作 `FileQuoteTerms` 的签名验证，不能解释成其他报文的签名。

正式 CDDL 位于 [`../spec/file-quote.cddl`](../spec/file-quote.cddl)。所有外层和子结构均使用 RFC 8949 core deterministic CBOR。

## 报价条款

`FileQuoteTerms` 的 CBOR 数组固定为：

| 位置 | 字段 | 说明 |
|---:|---|---|
| 0 | 条款版本 | 当前为 `1`。这是独立子结构的版本，不是报价数据库版本。 |
| 1 | `seed_hash` | 32 字节文件 seed 哈希。 |
| 2 | `buyer_pubkey` | 本报价唯一允许接受和购买的买方公钥。BitFS 报价只做 1 对 1。 |
| 3 | `seed_price_sat` | 购买 seed 的价格，单位 sat。 |
| 4 | `full_block_price_sat` | 购买一个完整 256 KiB 文件块的价格，单位 sat。 |
| 5 | `file_size` | 文件总字节数。块数由此推导，不作为冗余字段传输。 |
| 6 | `quote_expires_at_unix` | 报价失效的 Unix 秒时间戳。报价没有生效时间，收到后至失效前均可接受。 |
| 7 | `supported_arbiter_pubkeys_cbor` | 仲裁者公钥列表的独立 deterministic CBOR 编码。 |

块数由以下规则唯一推导：

```text
file_size = 0  →  block_count = 0
file_size > 0  →  block_count = ceil(file_size / 262144)
```

当前 seed 在一个 payload 中交付，payload 上限为 256 KiB；因此报价最大为 8192 个块、约 2 GiB 文件。超过这一上限的报价无效，直到协议引入分页 manifest。

仲裁者子结构是公钥 bytes 的数组。列表中公钥不得为空或重复；空列表编码为 CBOR 空数组，而不是 `null`。它表达卖方接受的仲裁者；后续买方购买请求必须从中选择一个具体仲裁者并签名。若未来要表达优先级，必须另行定义字段；当前数组不具有优先级语义。

## 报价凭证

`SignedFileQuote` 的 CBOR 数组固定为：

| 位置 | 字段 | 说明 |
|---:|---|---|
| 0 | 凭证版本 | 当前为 `1`。 |
| 1 | `terms_cbor` | 上述 `FileQuoteTerms` 的完整、确定性 CBOR 字节。 |
| 2 | `seller_pubkey` | 签发报价的卖方公钥。 |
| 3 | `terms_signature` | 卖方对 `terms_cbor` 的签名。 |
| 4 | `recommended_filename` | 未签名的下载文件名建议。 |

文件名不属于内容、价格、身份或履约真值。中继方可以修改它；客户端只能把它当作下载后的展示建议，并必须清理路径分隔符和控制字符。

## 条款哈希与后续报文

库提供：

```text
FileQuoteTermsHash = SHA256(TermsCBOR)
```

它是条款的内容指纹，可用于缓存、去重、日志和后续报文的轻量引用；它不是数据库生成的 ID，也不是业务真值本身。

后续买卖报文可以走两条路径：

- 正常高效路径：携带 `FileQuoteTermsHash`，卖方在本地缓存中取回 `TermsCBOR` 并验证。
- 自证路径：携带完整 `TermsCBOR + SellerPubkey + TermsSignature`，任何节点都可离线验真。

首次购买、缓存未命中、跨节点转发、审计和仲裁必须支持自证路径。卖方与买方都必须将完整报价凭证保留至所有基于该报价的交易已结算、且仲裁窗口结束；不能仅因报价失效就删除证据。

## 尾块价格

报价只承诺 seed 价和完整块价，不再传输尾块价。最后的残块可按其长度相对于 256 KiB 的比例计价，卖方应给予买方 10% 的计算让利。

该规则在本阶段是商业计算指南，不是可直接结算的唯一金额公式。后续购买凭证设计必须二选一：

- 定义唯一的整数舍入公式；或
- 由买方提出具体尾块金额，再由卖方在购买接受或交付凭证中签名确认。

在第二种模式完成前，任何实现都不得把模糊的“约 10%”当作可仲裁的精确支付金额。

## Go API

```go
arbiterCBOR, err := bitfs.EncodeSupportedArbiterPubkeys(arbiterPubkeys)
terms := &bitfs.FileQuoteTerms{
    SeedHash:                    seedHash,
    BuyerPubkey:                 buyerPubkey,
    SeedPriceSat:                10,
    FullBlockPriceSat:           100,
    FileSize:                    fileSize,
    QuoteExpiresAtUnix:          expiresAtUnix,
    SupportedArbiterPubkeysCBOR: arbiterCBOR,
}

quote, err := bitfs.NewSignedFileQuote(
    terms,
    sellerPubkey,
    "download.bin",
    signTermsCBOR,
)

verifiedTerms, err := bitfs.VerifySignedFileQuote(
    quote,
    verifySellerTermsSignature,
)
```

`signTermsCBOR` 接收确切的 `TermsCBOR` 字节并返回签名。`verifySellerTermsSignature` 接收卖方公钥、同一份 `TermsCBOR` 与签名。库不绑定钱包、曲线或签名实现；部署方必须统一规定公钥格式、签名算法和验签器。

## 与旧 V1 `FileQuote` 的关系

旧 `FileQuote` 没有卖方签名，也无法与后续票据建立自证关系。它保留在当前库中仅为 V1 兼容。新接入应使用本规范的 `SignedFileQuote` API。

`HashGetTicket` 尚未重构为携带或引用报价凭证；这会在后续“买方购买请求”报文设计中完成，不能通过悄悄修改旧 V1 字段实现。
