# 006 · 费用池无条件关闭规范

本规范定义费用池的到期退款与卖方仲裁提交。它是通用 2-of-3 费用池能力，不引用 BitFS 报价、seed、内容请求或交付凭证作为买方关闭条件。

## 买方到期退款

买方无须向卖方发送关闭请求、等待卖方签名或请求仲裁。买方只需等待到期：卖方从未提交累计付款状态时，买方提交 002 `RefundTx` 获得全额退款；卖方已提交最新累计付款状态时，该状态本身在到期后结算，交易输出直接给出卖方累计金额及买方找零，不存在后继找零交易。

实现必须：

1. 验证到期条件已满足；
2. 若未有卖方提交的累计付款状态，则使用 002 保存的完整 `RefundTx`、来源输出描述和双方退款签名；
3. 通过支持 BSV 非最终交易池的提交能力提交退款交易；该节点若已保存更高的累计状态，必须拒绝这笔较旧退款；
4. 将返回交易 ID 与待提交交易内容计算的交易 ID 比较。

这里的“使用 RefundTx”表示先由交易引擎把证明中分离保存的买方、卖方签名装配进 unlocking script，再把装配后的原始交易提交给节点；证明中的 RefundTx 原始字节仍是 SpendTxID 的稳定锚点。

买方不提供应用层关闭请求或关闭金额，不得因卖方未提交付款交易向仲裁者发送关闭报文。

## 卖方累计状态提交

卖方可按 005 使用买方已签出的累计付款状态。卖方提交的交易必须严格符合该状态的序号和累计金额；卖方不得自行提高卖方金额、使用较小或重复序号，或使用未验证的内容请求作为付款依据。正常付款序号允许大于前一状态而跳号。

买方到期后的找零由实际已提交且有效的累计状态中的买方输出决定。卖方未提交任何累计状态时，买方的 002 退款交易返回全额资金。实现不得把已提交状态误解为需要再构造一笔买方找零交易。

## 卖方仲裁提交

卖方在无法正常提交买方已签出的累计付款状态时，按 [007-卖方仲裁提交规范](007-卖方仲裁提交规范.md) 向仲裁者提交完整开池证明、003 最终付款授权、空解锁候选交易和 server 签名。仲裁者只验证该候选交易并以 B 签名；不得自行增加卖方金额、向买方收费、构造交易或裁定额外赔偿。

## V1 费用边界

V1 不定义仲裁服务费字段，不允许从费用池余额中静默扣取仲裁服务费。卖方承担仲裁服务的池外费用，或为待提交交易提供额外输入。支持池内仲裁费、赔偿或罚款必须另行定义协议。

## 交易安全限制

006 依赖 005 的 BSV 非最终交易池覆盖机制，使“最新累计状态、卖方提交、买方到期退款”能够安全共存。实现必须通过支持该机制的节点接口提交和核验状态。
