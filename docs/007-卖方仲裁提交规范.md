# 007 · 卖方仲裁提交规范

本规范定义卖方向仲裁者提交累计付款状态、请求仲裁交易签名的实施约束。它只适用于卖方；买方不得使用本规范请求关闭、退款或金额裁定。

## 证据包

仲裁请求使用一个 deterministic CBOR 外层数组。每一项子凭证必须以其**原始确定性 CBOR 字节**作为 `bytes` 放入，不得只放哈希、JSON、数据库 ID 或重新编码后的近似副本。

| 位置 | 字段 | 实施要求 |
|---:|---|---|
| 0 | `version` | 当前为 `1`。 |
| 1 | `pool_opening_proof_cbor` | 完整 002 `PoolOpeningProof` 原始 CBOR。 |
| 2 | `latest_payment_state_cbor` | 买方已签出的最后完整累计付款状态原始 CBOR；必须包含花费同一基础输出的交易数据、支付序号、累计金额及买方交易签名。 |

`latest_payment_state_cbor` 使用 005 `CumulativePaymentUpdateCBOR`：其中的原始部分签名 BSV 交易和买方签名是仲裁付款真值。007 不得自行发明 `proposal_id`、服务端状态或仲裁金额字段。

## 仲裁者校验

仲裁者必须：

1. 解码并验证完整开池证明、资金来源、2-of-3 锁定脚本、公钥顺序和 `SpendTxID`；
2. 从开池证明确定卖方和仲裁者公钥，不接受请求方另行声明的身份或仲裁者；
3. 验证 `latest_payment_state_cbor` 的买方签名、非最终 `nSequence`、累计金额和交易输入均符合 005；
4. 验证最后状态中的待执行交易严格对应其买方已签名的交易数据、输入、输出、金额和签名摘要；
5. 验证该交易没有把仲裁费、赔偿或额外卖方金额从费用池余额中扣除；
6. 对同一笔待执行交易产生仲裁者所需的原始交易签名。

仲裁者不得查询买卖双方的数据库来补齐缺失证据；不得依据 001、003、004 重新计算卖方应得金额；不得自行修改交易、支付序号或累计分配。

## 仲裁响应

仲裁响应只返回：

| 字段 | 实施要求 |
|---|---|
| `latest_payment_state_hash` | `SHA256(latest_payment_state_cbor)`，32 字节，用于让卖方匹配本次响应。 |
| `arbiter_transaction_signature` | 仲裁者对该状态中同一待执行交易产生的原始交易签名。 |

响应不包含 `approved`、`reason_code`、`final_payout_sat`、仲裁数据库 ID 或新的金额真值。卖方验证仲裁签名、合并交易后，通过调用方提供的交易提交能力提交。

## 保存与费用

仲裁服务可缓存证据包和处理结果以实现重试或收费，但缓存不是仲裁真值。每次需要签名时必须能够仅依赖提交的完整证据包完成验证。

V1 不定义 `ArbiterFeeSat`。仲裁服务费由卖方在池外支付，或由卖方为待提交交易提供额外输入；实现不得从费用池累计分配中静默扣费。

## 非目标

- 不受理买方关闭、买方退款或买方金额争议；
- 不在本步骤传输仅供业务解释的 001、003、004 历史链，或据此重算金额；
- 不把 `SpendTxID`、状态哈希或任意服务端记录当作可单独验证的仲裁证据。
