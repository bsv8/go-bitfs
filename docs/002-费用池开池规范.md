# 002 · 通用 2-of-3 费用池开池规范

本规范只定义通用 2-of-3 费用池开池。开池报文不得包含 `seed_hash`、报价、文件哈希、文件名、块序号、购买请求或价格。

## 固定交易约束

池输出锁定脚本的公钥顺序固定为：

```text
[buyer_pubkey, seller_pubkey, arbiter_pubkey]
```

`RefundTx` 必须花费唯一的 `PoolOutpoint`，包含买方和卖方交易签名、链上到期条件，并在到期后将可花费余额退回买方；初始卖方分配固定为 `0`。退款交易矿工费从池金额扣除。

`SpendTxID` 是双方退款交易签名齐备后的 `RefundTx` 规范交易 ID。双方必须计算并保存同一值。003 以后以：

```text
SpendTxID + BasePaymentSequence
```

引用费用池状态。`SpendTxID` 不得替换为服务端会话 ID 或每次付款更新产生的交易 ID。

## 报文编码

外层报文和独立证明使用 deterministic CBOR。正式数组位置见 [`../spec/v1/settlement.cddl`](../spec/v1/settlement.cddl)。原始交易、交易签名和锁定脚本均为 `bytes`。

### `PoolRefundPresignRequest`

方向：买方 → 卖方；不得包含 `FundingTx`。

| 字段 | 实施要求 |
|---|---|
| `version` | 当前为 `1`。 |
| `refund_tx` | 确定的 `RefundTx` 原始字节。 |
| `funding_txid` | 必须等于退款交易唯一输入的来源交易 ID。 |
| `pool_output_index` | 必须等于退款交易输入的来源输出索引。 |
| `pool_output_satoshis` | 退款交易签名摘要所需的来源金额。 |
| `pool_locking_script` | 退款交易签名摘要所需的精确 2-of-3 脚本。 |
| `buyer_refund_signature` | 买方对 `refund_tx` 的交易签名。 |

卖方必须生成自己的退款交易签名，并在返回前保存请求材料和签名。

### `PoolRefundPresignResponse`

方向：卖方 → 买方。

| 字段 | 实施要求 |
|---|---|
| `version` | 当前为 `1`。 |
| `seller_refund_signature` | 对请求中同一退款交易和来源输出描述的交易签名。 |

买方必须验证卖方签名，并在发送资金交易前保存完整开池证明。

### `PoolFundingTxDelivery`

方向：买方 → 卖方。

| 字段 | 实施要求 |
|---|---|
| `version` | 当前为 `1`。 |
| `funding_tx` | 买方已签名的 `FundingTx` 原始字节。 |

卖方收到后必须：计算 `funding_txid`；找到已保存的待激活证明；逐项验证资金交易 ID、输出索引、金额、锁定脚本、退款交易输入以及双方退款签名；保存完整证明；调用交易提交能力。提交返回的交易 ID 必须等于从 `funding_tx` 计算的 ID。

## 流程顺序

```text
1. 买方本地构造 FundingTx、RefundTx 并签 RefundTx。
2. 买方发送 PoolRefundPresignRequest。
3. 卖方签 RefundTx，保存待激活证明，发送 PoolRefundPresignResponse。
4. 买方验签，保存完整退款证明，计算并保存 SpendTxID。
5. 买方发送 PoolFundingTxDelivery。
6. 卖方验证 FundingTx，保存完整证明，提交 FundingTx，计算并保存 SpendTxID。
```

买方在第 4 步完成开池；卖方在第 6 步交易提交接口成功返回时完成开池。实现不等待确认数或链上监听结果。

## 证明保存与外部能力

`PoolOpeningProof` 必须保存退款交易、来源输出描述、双方退款签名，以及收到后的 `FundingTx`。它可编码为 deterministic CBOR；其哈希用于去重和证据包，不能代替 `SpendTxID` 作为后续状态引用。

SDK 通过以下能力接口访问外部系统：

```go
type PoolOpeningProofStore interface {
    SavePoolOpeningProof(ctx context.Context, proof *PoolOpeningProof) error
    LoadPoolOpeningProofByFundingTxID(ctx context.Context, fundingTxID []byte) (*PoolOpeningProof, error)
}
type RefundTxSigner interface {
    SignRefundTx(ctx context.Context, request *PoolRefundPresignRequest) ([]byte, error)
}
type RefundTxSignatureVerifier interface {
    VerifySellerRefundSignature(ctx context.Context, request *PoolRefundPresignRequest, signature []byte) error
}
type TransactionIDCalculator interface {
    TransactionID(ctx context.Context, rawTx []byte) ([]byte, error)
}
type FundingTxVerifier interface {
    VerifyFundingTx(ctx context.Context, fundingTx []byte, proof *PoolOpeningProof) error
}
type TransactionSubmitter interface {
    SubmitTransaction(ctx context.Context, rawTx []byte) ([]byte, error)
}
```

`SellerPresignRefund` 必须先保存再返回签名；`BuyerAcceptRefundPresign` 必须先验签并保存再交付资金交易；`SellerAcceptFundingTx` 必须先验证和保存再提交。

开池证明、报价凭证和后续支付状态由调用方实现的存储能力保存；SDK 不实现服务端、数据库、链节点或网络传输。
