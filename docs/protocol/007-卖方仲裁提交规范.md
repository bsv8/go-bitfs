# 007 · 卖方仲裁提交规范

本规范定义卖方依据买方最终付款授权请求 `server+B` 仲裁签名的实施约束。它只适用于卖方；买方不得使用本规范请求关闭、退款或金额裁定。当前协议 major 为 2。

## 证据包

仲裁请求使用一个 deterministic CBOR 外层数组。每一项子凭证必须以其**原始确定性 CBOR 字节**作为 `bytes` 放入，不得只放哈希、JSON、数据库 ID 或重新编码后的近似副本。

| 位置 | 字段 | 实施要求 |
|---:|---|---|
| 0 | `version` | 当前为 `2`。 |
| 1 | `pool_opening_proof_cbor` | 完整 002 `PoolOpeningProof` 原始 CBOR。 |
| 2 | `payment_authorization_cbor` | 买方签署的完整最终付款授权；它自包含池锚点、base/target 序号、绝对卖方金额、整数费率和 server/A/B 公钥。 |
| 3 | `unsigned_state_tx_raw` | 卖方依据最后授权和当前接受状态构造的两输出候选交易；输入解锁脚本必须为空。 |
| 4 | `seller_transaction_signature` | 卖方对同一无解锁脚本候选交易的 server 签名。 |

007 不携带 `latest_payment_state_cbor`，也不要求买方为本次争议签署 005。候选交易由卖方根据最后授权和当前接受状态构造，授权中的绝对卖方金额是唯一业务金额真值。007 不得自行发明 `proposal_id`、服务端状态或仲裁金额字段。

## 仲裁者校验

仲裁者必须：

1. 解码并验证完整开池证明、资金来源、2-of-3 锁定脚本、公钥顺序和 `SpendTxID`；
2. 从开池证明确定卖方和仲裁者公钥，不接受请求方另行声明的身份或仲裁者；
3. 验证最终授权 deterministic CBOR 和买方签名，并确认其中 server/A/B、费率、SpendTxID 与开池证明一致；
4. 通过 MultisigPool 验证无解锁候选交易的输入、序号、绝对卖方金额、整数费率和两个输出；
5. 验证卖方 server 签名；
6. 对同一无解锁候选交易产生 B 签名。

仲裁者不得查询买卖双方的数据库来补齐缺失证据；不得依据 001、003、004 重新计算卖方应得金额；不得自行修改交易、支付序号或累计分配。

## 仲裁响应

仲裁响应只返回：

| 字段 | 实施要求 |
|---|---|
| `payment_authorization_hash` | `SHA256(payment_authorization_cbor)`，32 字节。 |
| `unsigned_state_tx_hash` | `SHA256(unsigned_state_tx_raw)`，32 字节。 |
| `arbiter_transaction_signature` | 仲裁者对该状态中同一待执行交易产生的原始交易签名。 |

响应不包含 `approved`、`reason_code`、`final_payout_sat`、仲裁数据库 ID、仲裁费或新的交易模板。卖方复核两个哈希和 B 签名，按 `server+B` 合并后提交。

## 保存与费用

仲裁服务可缓存证据包和处理结果以实现重试或收费，但缓存不是仲裁真值。每次需要签名时必须能够仅依赖提交的完整证据包完成验证。

V1 不定义仲裁服务费字段。仲裁服务费由卖方在池外支付，或由卖方为待提交交易提供额外输入；实现不得从费用池累计分配中静默扣费。

## 非目标

- 不受理买方关闭、买方退款或买方金额争议；
- 不在本步骤传输仅供业务解释的 001、003、004 历史链，或据此重算金额；
- 不把 `SpendTxID`、状态哈希或任意服务端记录当作可单独验证的仲裁证据。
