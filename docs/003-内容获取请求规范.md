# 003 · 内容获取请求规范

本规范定义买方请求卖方交付 seed 或文件块的报文。它只建立“请求某个确定内容、并指定将来从哪个费用池状态付款”的买方承诺；不得推进费用池金额，不得包含付款交易。

## 真值与签名

```text
ContentRequestTermsCBOR = deterministic CBOR(ContentRequestTerms)
BuyerSignature = Sign_buyer(ContentRequestTermsCBOR)
ContentRequestTermsHash = SHA256(ContentRequestTermsCBOR)
```

不使用签名域。买方公钥从 `QuoteTermsHash` 所指向、并经卖方签名验证的 001 报价条款中取得。

`ContentRequestTerms` 的数组位置固定为：

| 位置 | 字段 | 中文说明 |
|---:|---|---|
| 0 | `version` | 条款版本，当前为 `1`。 |
| 1 | `quote_terms_hash` | 001 `FileQuoteTermsCBOR` 的 SHA-256，32 字节。 |
| 2 | `spend_txid` | 所选费用池的稳定花费交易 ID，32 字节。 |
| 3 | `base_payment_sequence` | 该池当前最新累计支付状态序号。 |
| 4 | `selected_arbiter_pubkey` | 买方为该次购买选择的仲裁公钥。 |
| 5 | `content_type` | `0 = Seed`，`1 = Block`。 |
| 6 | `content_hash` | 请求内容的 32 字节哈希。 |
| 7 | `delivery_deadline_unix` | 最晚交付 Unix 秒时间。 |

外层 `SignedContentRequest` 固定为：

| 位置 | 字段 | 中文说明 |
|---:|---|---|
| 0 | `version` | 凭证版本，当前为 `1`。 |
| 1 | `terms_cbor` | 完整 `ContentRequestTermsCBOR` 原始字节。 |
| 2 | `buyer_signature` | 买方对 `terms_cbor` 的签名。 |

## 卖方必须验证的事项

1. 用 `quote_terms_hash` 找回并验证自己签发的 001 报价；报价尚未失效，且其中买方公钥能验证 `buyer_signature`。
2. `selected_arbiter_pubkey` 在报价允许列表内，并与该 `spend_txid` 所保存费用池证明中的仲裁公钥相同。
3. `spend_txid` 对应费用池由报价中的买卖双方共同建立；`base_payment_sequence` 恰好是该池当前最新累计状态。
4. `content_type = Seed` 时，`content_hash` 等于报价 `seed_hash`；`content_type = Block` 时，该哈希存在于对应 seed 的块哈希列表中。
5. `delivery_deadline_unix` 尚未来临，并符合卖方可接受的交付窗口。
6. 池中买方可用余额足以支付本内容按报价推导的金额和后续状态更新所需费用。
7. 该费用池没有另一张被卖方接受且尚未完成的内容请求。卖方必须原子地建立该请求的进行中门闩后，才可交付 004；门闩规则见 005。

`base_payment_sequence` 不是内容顺序。它只是费用池版本；种子和任意块的请求都可以引用任意可用池的当前最新序号。

## 引用与证据

正常报文只带 `quote_terms_hash`，不重复报价原文。双方必须保存 001 报价凭证和已签名的 003 请求。需要离线验证、设备迁移或仲裁时，证据包至少包含：001 报价凭证、003 请求凭证、相应费用池开池证明与累计状态证明。

004 必须引用 `ContentRequestTermsHash`，不得复述本规范中的字段。

## 非目标

- 不在本报文中携带报价价格、文件大小、块索引、块大小、文件名、买卖双方公钥或报价原文；
- 不在本报文中创建付款交易或变更 `BasePaymentSequence`；
- 不使用数据库会话 ID、票据 ID 或块序号替代上述内容哈希和条款哈希。
