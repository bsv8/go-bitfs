# 004 · 内容交付凭证需求

## 要解决什么

卖方收到 003 后，需要交付种子本体或文件块本体。交付不能把报价、费用池、仲裁者和请求参数逐项回传；它只要明确回答“这是对哪一张买方请求的交付，以及交付的确切字节是什么”。

## 最小交付关系

004 引用 `PaymentAuthorizationHash`，并带内容字节。卖方对这两项组成的确定性 CBOR 签名。买方从自己保存的 003 恢复所有购买条件，校验卖方身份、内容哈希和交付截止时间；通过后才进入付款。

```text
003：买方签名地请求确定内容
004：卖方签名地交付确定字节
005：买方验收后推进累计支付状态
```

## 交付时限的边界

`DeliveryDeadlineUnix` 来自 003。买方应以实际收到并验证交付包的本地时间决定是否接受；卖方自行填写一个时间戳不能证明网络上何时送达，因此 v3 不把卖方声明时间当作客观证据。

卖方的 004 签名能证明卖方声明并绑定了这些内容字节，但不能单独证明买方实际收到。买方在 005 对付款状态的签名，才是验收并付款的强证据。若将来仲裁要裁定“卖方是否按时送达而买方拒付”，须另行引入可证明接收或仲裁转交机制。

具体字段和校验规则见[内容交付凭证规范](004-内容交付凭证规范.md)。
