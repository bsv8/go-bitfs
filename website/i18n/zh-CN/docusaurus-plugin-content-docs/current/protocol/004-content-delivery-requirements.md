# 004 · 内容交付凭证需求

## 要解决什么

卖方收到 003 后，需要交付种子本体或文件块本体。交付不能把报价、费用池、仲裁者和请求参数逐项回传；它只要明确回答“这是对哪一张买方请求的交付，以及交付的确切字节是什么”。

## 最小交付关系

004 携带费用池 `RefundTemplateTxID` 关联 ID，并引用 `PaymentAuthorizationHash` 与内容字节。卖方对这三项的确定性 CBOR 编码签名，因此可独立投递的凭证能直接路由到其费用池。买方从本地保存的 opening proof 重新派生 `RefundTemplateTxID`，要求其与 003 条款 hash 字段和已签名的 004 交付 hash 字段全部相等，并验证卖家身份、内容哈希和交付期限；全部通过后才进入付款。

```text
003：买方签名地请求确定内容
004：卖方签名地交付确定字节
005：买方验收后推进累计支付状态
```

## 交付时限的边界

`DeliveryDeadlineUnix` 来自 003。买方应以实际收到并验证交付包的本地时间决定是否接受；卖方自行填写一个时间戳不能证明网络上何时送达，因此 v4 不把卖方声明时间当作客观证据。

卖方的 004 签名能证明卖方声明并绑定了这些内容字节，但不能单独证明买方实际收到。买方在 005 对付款状态的签名，才是验收并付款的强证据。若将来仲裁要裁定“卖方是否按时送达而买方拒付”，须另行引入可证明接收或仲裁转交机制。

具体字段和校验规则见[内容交付凭证规范](004-content-delivery-spec.md)。
